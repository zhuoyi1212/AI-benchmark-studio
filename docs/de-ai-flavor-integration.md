## 项目适配

八项检查用于定位具体语言问题：框架词、空泛高频词、强行对仗、句式同构、已有判断/情感表达、具体细节、书面腔和冗余。结合本次反馈，重点检查平均分配的文字/布局/风格三段、段末盖章、Prompt式开头和报备式结尾。不是逐词禁令，准确的正式表述与有信息的结构可以保留。

原文原样保留在静态副本；项目契约明确覆盖不适合本产品的部分：

| 原Skill约定 | 产品中的处理 |
| --- | --- |
| 输出体检报告、浓度分数、改动摘要及全文 | 仅返回当前阶段的严格JSON字段；问题进入既有quote/reason/instruction，不塞进正文 |
| 按八项权重打分 | 不把主观编辑分数当AI生成概率、真实性或ready门槛 |
| 缺少情绪/个人判断算一项检查 | 没有真实情绪记录不扣分、不强迫补写；靠具体观察与有据评价表达 |
| 原长±20%、低于约85%要补回 | 不设新篇幅下限；可删重复与无关参数，支持判断的细节、数字、引语和不同条件仍受保护 |
| 原文信息点保留 | 选材仍服从验证过的Brief，不要求把事实账本全写出来；修订删除数字/引语仍须明确定位指令 |

“我最担心”“我盯着看了半天”“居然没乱放”不能作为通用真人感配方；它们含感受或执行过程，需要作者输入/测试记录。参考视频的这些内容不属于本次作者。

## 流程与验收

沿用`策划 → Skill指导初稿 → 只读初审 → 按问题进行一次Skill指导修订 → 独立只读终审`，无需修订时仍四阶段。没有新增Agent、循环润色、评分器、模型、依赖或表。

策略升到`community-story.v13-de-ai-flavor`；四条涉及写作/修订/文本审核/视觉审核的Prompt分别升版。原Skill、项目契约、任务和证据进入实际消息及输入签名，旧检查点不会冒充新结果。最终审核对象就是实际保存文案；事实、范围、经历、证据、数字和引用门禁不变。

新增回归验证完整原文/许可/哈希、快/专业真实Service请求、无情绪也能完成、严格字段隔离、定位后删重复不受篇幅下限、数字保留及终审拒绝。模型调用使用隔离夹具，未向Provider发送用户新文案、未改生产记录。工程通过不等于风格已获用户认可；需要同源真实样稿和读者比较。
