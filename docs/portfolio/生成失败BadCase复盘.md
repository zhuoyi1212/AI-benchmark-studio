# 重新生成失败：从错误提示到质量闭环

整理日期：2026-10-16，清理验收于北京时间2026-10-17完成，属于项目后续个人迭代。实现与排查由本人和 Codex 协作完成；个人职责的最终表述由本人确认。

## 1. 问题与影响

多个测评项目点击“重新生成”后失败，界面仅显示结构校验或最终保真检查未通过。用户无法判断是原始材料、模型输出、审核规则还是后台执行出了问题，重复点击也未必能解决。

产品目标：基于已有真实测试材料生成可核对的新稿；失败能定位到具体阶段，旧稿保持可用。不能通过跳过事实审核获得表面成功。

## 3. 根因与取舍

| 类别 | 证据与定位 | 修复或处理 | 产品判断 |
| --- | --- | --- | --- |
| 截图读取结构错误 | 即梦 v5/v6，视觉输出出现非法 JSON 或 `answer` 包装，与 `observations` Schema 不一致 | 明确根结构、数量与转义规则；同供应商有界修复时保留原图片和标签顺序。提交 `68cf438` | 格式失败应在读取节点发现，不能继续拿缺失材料写稿 |
| 后台任务串写版本 | 元宝旧任务恢复时误关联新版本；新任务随后提示重新生成记录无效 | 绑定任务目标和 lease，去除宽泛的时间范围恢复，隔离新旧版本。提交 `4f953d5` | 重试必须继续自己的任务，不能因“找最新文章”写入别人的版本 |
| 审核意见指错对象 | 元宝审核意见引用 Brief 中的“可核对后引用”，并非最终正文原句 | 审核问题必须定位到当前稿件字段和原句，原因与定位一致。提交 `4f953d5` | 审核器也会误判，应评估误拦截，不能将所有失败当作内容不合格 |
| 规则过宽、修订后才拦截 | 懂你AI“容易踩的坑”被宽泛词规则误拒；v8 修订引入“值得注意的是”，最终门禁才报报告腔 | 收窄行为断言匹配，修订后立即执行一致规则并给出实际问题短语。提交 `4f953d5`、`3d7b195` | 硬规则应针对可解释的风险，前后校验口径需一致 |
| 审稿结构含混 | 即梦 v9 在 **DeepSeek 文本初审**失败：嵌套 `articleReview.issues` 与根层 `issues` 的字符串/对象类型混淆；此前图片读取已完成 | 提供两层不同类型的完整示例，统一文本/视觉修复契约。提交 `3d7b195` | 有图片的项目不等于每一步都是视觉模型，应按实际任务追踪 |
| 上游图片解析拒绝 | 即梦 v10：Z.AI HTTP 400 / 1210；四张原图可下载且 PNG 签名、尺寸有效 | 保留失败，正常新建 v11 并重新获取签名链接后通过；不认定已找到供应商根因 | 区分可验证事实与根因假设，单次重试成功不等于接口问题已根治 |

即梦 v7 的“不用改”属于缺少直接依据的断言，被正确拦截。它与审核误拦截应分开计数，不能因为最终需要文章就统一放宽门禁。

详细时间线、原始任务与调用依据见[重生成可靠性排查](../regeneration-reliability-20261016.md)。其余历史失败见[归档清单](assets/badcases/archive-manifest.json)，未完整复现的旧错误只记现象，不补写根因。

## 5. App 清理与证据保留

本次按用户要求，将 App 可见项目中的失败文章及失败后台任务归档后清理。首轮快照包括 25 条失败文章、9 条失败生成任务、33 条关联阶段记录；最终核查又归档了 4 条更早的方案/评分/分析失败任务及 1 条阶段记录。合计 25 条失败文章、13 条失败任务、34 条阶段记录；失败文章未关联 `publish_pack_artifacts`。内部验证项目、已删除项目不在本次范围。正常稿件、原始 Artifact、方案、评分、人工纠偏、Findings 和 Storage 文件保留。

完整原始备份位于本地 `outputs/badcase-archive/2026-10-16/backup.private.json`，补充任务备份位于 `outputs/badcase-archive/2026-10-17-other-jobs/backup.private.json`；目录仅本机用户可读，已加入 Git 忽略。这些备份可能包含原始输入与签名链接，不随求职作品集外发。公开清单只保留记录 ID、错误、阶段、模型版本和文件校验值，不含原始任务输入、密钥或可访问的签名链接。

本轮 431 项测试、typecheck、build（含媒体自检）及差异检查通过；lint 为 0 错误、26 条既有警告。无需应用部署或重新调用模型。详见[归档清单](assets/badcases/archive-manifest.json)中的 `cleanup`。截图保存 SHA-256，文章版本号不重新编号。

**清理 App 展示不改变历史效果统计。**后续计算首次成功率、重试成功率和成本时，应使用完整归档，将失败和重试成本计入分母；不得仅以清理后可见稿件宣称 100% 成功。

## 6. 面试讲述

> 在真实项目重新生成时，我发现多次失败被同一条“校验未通过”提示掩盖。与 Codex 排查任务、模型返回和规则后，区分了结构错误、版本串写、审核误判及供应商错误，分别补充节点契约、任务隔离和审核定位。三个项目后来完成了真实材料回归；同时保留失败截图和日志，作为后续评估审核误杀与链路成功率的案例。现阶段还不能给出总体幻觉率或降本幅度。

待补设计：前台显示可执行的错误原因；建立独立人工标注的审核漏检/误拦截集；固定样本和版本后统计端到端采用率及重试成本。这些方向尚未因本次归档而自动完成。
