# 工作流节点设计与评测标准

日期：2026-10-16。配套[作品集完整方案](作品集完整方案.md)。覆盖现有产品及待补评估设计，不修改生产规则。

## 共同约定

节点输出由程序校验、人或模型检查后才能进入下游。每个AI节点分两种评估：固定合格输入测该节点自身能力；真实上游输出测误差传播与整链路效果。前者用于定位，后者用于业务验收。

所有节点记录实际输入版本、输出版本、状态、耗时与错误。AI节点另记录实际路由、模型、Prompt、签名、token和费用是否可得。以下“评测”均为待开展的统一量化方案，现有测试只能证明其中部分软件规则。

## N00 测评目标与项目创建

- **AI任务：**无。
- **目标：**由用户说明要测什么、为谁写；程序建立项目，确定单/多产品及快速/专业模式。
- **输入：**项目名称、测评意图、1–3个产品及可选官网；已有产品使用稳定身份，不能靠相同域名静默合并。
- **输出：**真实projectId、产品关联、模式与持久化意图；创建失败不返回假项目。
- **验收：**数量、名称冲突与字段规则合法，刷新可读；真实写入需管理员授权。意图是否清楚用人工判断，不自动补成真实用户需求。
- **评测：**合法/非法/重名/官网冲突/重复提交用例；另标注意图能否转化为具体任务，分别报告输入问题和程序问题。
- **异常：**校验失败保留输入并提示；保存失败明确失败；不跳转固定demo。
- **现状：**创建与持久化已有。意图清晰度统一标注待补。来源：[产品规范](../../PRODUCT_SPEC.md)、[项目创建服务](../../lib/services/projects.service.ts)。

## N01 产品调研与可比性

- **AI任务：**`research_search`、`research`、`comparability`。
- **目标：**检索和整理产品事实；多产品提炼共同能力与比较边界，单产品提炼可测试能力。
- **输入：**产品名称、提交官网、测评意图；综合阶段只依据检索材料，可比性只依据已保存Research。
- **输出：**定位、用户、能力、价格或null、限制、输入输出格式、来源；可比性状态、原因与共同能力。保留ResearchRun版本和时间。
- **验收：**来源URL来自检索结果，优先官方；未知不凭记忆填补；不得把官方承诺当实测效果。字符上限、文件支持须有来源，未查明不当作确定支持。
- **评测：**人工逐条检查关键主张的来源支持、产品归属、时效和重要信息覆盖；可比性与独立人工判断对照。来源有效率与主张支持率分开统计。
- **异常：**检索/格式失败按实际路由有限重试；资料不足保存限制或明确失败，不回退Mock；需重新调研时创建新版本。
- **现状：**Schema和来源校验已有；逐主张引用、覆盖率与事实支持统计待补。来源：[Research服务](../../lib/services/research.service.ts)、[Schema](../../lib/ai/schemas/research.schemas.ts)。

## N02 测试方案生成与锁定

- **AI任务：**`protocol`。
- **目标：**生成可执行、可留证、能回答测评意图的任务。专业模式使用实际任务路由`protocol_professional`。
- **输入：**指定ResearchRun、产品能力与输入限制、意图、模式；多产品只取共同能力与最小已知字符上限。
- **输出：**Protocol版本、目标、规则、TestCase、Prompt、必要输入材料和动态Rubric；快速模式1个任务，专业模式2–4个。
- **验收：**权重总和100%，任务数/字段合法；Prompt与附件兼容；至少一个有效任务。看到结果前锁定，锁后修改新建版本，不覆盖历史。
- **评测：**程序测权重和输入边界；人工按相关性、原生工作流、可执行性、可留证性、可评分性检查，失败项逐项解释；记录实际执行时被迫改Prompt的情况。
- **异常：**不能用截断掩盖不可执行任务；用户可在锁定前删除不合适任务，至少保留1个；不合格不允许锁定。
- **现状：**生成、权重、输入兼容与锁定已有；人工语义评分和真实执行通过率待补。来源：[Protocol Schema](../../lib/ai/schemas/protocol.schemas.ts)、[可执行性检查](../../lib/protocol-feasibility.ts)。

## N03 人工实测与原始证据上传

- **AI任务：**无。
- **目标：**人按锁定方案在第三方产品完成测试，保存原始结果；工作台不代替人自动测试。
- **输入：**Locked Protocol、TestRun、原始文件或逐字文本、生成时间/重试/编辑记录与备注。
- **输出：**TestRun状态、Artifact元数据、私有Storage对象与可追溯关系；确认全部测试结果后才可分析。
- **验收：**同任务的输入与执行条件一致，默认单次生成；每个TestRun至少一个通过类型、大小、文件头等校验的Artifact。预期输出类型是参考，不以类型不匹配拒绝有效原始结果。
- **评测：**上传成功、部分失败、响应丢失和重试用例；人工检查记录完整性与原始性。实测耗时计入业务人工成本，不计入模型延迟。
- **异常：**Storage/DB半成功需补偿或幂等确认；失败项可重试，成功项不重复上传；不生成替代证据或把手改结果冒充首轮输出。
- **现状：**直传、校验、持久化与补偿已有；统一执行遵从率和工时统计待补。来源：[测试服务](../../lib/services/test-execution.service.ts)、[产品规范](../../PRODUCT_SPEC.md)。

## N04 证据读取与媒体处理

- **AI任务：**`video_frame_analysis`、`screenshot_understanding`；OCR为可选辅助任务`ocr`，并非所有文件默认执行。
- **目标：**把已上传材料转为下游可读取且能追溯的证据，区分提取失败与产品表现。
- **输入：**Artifact、SHA-256、类型、任务上下文与锁定的媒体选择规则；原始文本、PDF/图片或视频。
- **输出：**原文或受控视觉输入；视频产生MediaEvidence，包括时间戳、帧观察、字幕、转录状态、采样信息、warnings与实际模型元数据。
- **验收：**不能静默截取后宣称完整；混合媒体按已实现兼容策略处理。视频最多12帧、原始MP4不发AI；ASR未接入时为unavailable，不能推断无配音或声画质量。
- **评测：**程序查哈希/引用/时间戳、损坏与超限；人工按原始媒体核对观察正确性、遗漏与抽样限制。帧提取成功率、视觉观察质量及全片覆盖度分开。
- **异常：**部分失败保留warnings，仍有有效证据可继续；无有效证据明确失败。分析工具故障不能记作被测产品缺陷。
- **现状：**预处理和证据结构已有；ASR未接入；语义观察准确性及关键事件遗漏评估待补。来源：[媒体规范](../video-media-evidence.md)、[MediaEvidence Schema](../../lib/media/media-evidence.ts)。

## N05 匿名评分 Judge

- **AI任务：**`judge_text`、`judge_multimodal`、`judge_video_evidence`。
- **目标：**依据锁定的评分标准评价可观察输出，不获得真实产品身份。
- **输入：**Locked Protocol、Case、Rubric、Blind Sample与实际选用的原始/派生证据；不传真实产品映射。输入中的品牌文字和图像身份线索亦需作为盲测泄漏检查对象。
- **输出：**每个Sample×维度的aiScore、reason、evidence和confidence；每Case绑定唯一JudgeCaseRun与实际路由。
- **验收：**分数0–10且最多1位小数，矩阵完整、无重复/未知引用；同Case全部Sample共享Provider/模型/Prompt。原始评分、理由与证据不可人工覆盖。
- **评测：**程序测矩阵、路由和引用；独立人工不先看AI分数，以同Rubric标注后比较偏差与排序。离线交换样本位置、重复内部评价，检查位置偏差和稳定性。
- **异常：**无共同有效媒体或评分失败时停止，支持同Provider有限重试；不得漏掉一个Sample仍给比较结论，不生成假评分。
- **现状：**评分与路由机制已有；专家/人工校准、位置偏差和confidence校准待补。来源：[Judge服务](../../lib/services/judge.service.ts)、[评分Schema](../../lib/ai/schemas/judge.schemas.ts)。

## N06 人工复核 锁定与揭盲

- **AI任务：**无新增模型任务。
- **目标：**复核异常评分，锁定后揭盲；人工修改只纠偏具体维度。
- **输入：**匿名评分、原始证据、异常标记、reviewing状态；快速模式正常项按规则自动接受，异常项由人处理。
- **输出：**append-only override/revert事件、理由、Final Score、locked/revealed状态；最终分由有效人工修正或AI分单一推导。
- **验收：**先锁定再揭盲，锁后不能普通编辑；人工理由必填，不能直接改Overall。当前confidence<0.8是异常触发规则之一，不代表模型低于80%准确率。
- **评测：**程序测试越序访问、改分/恢复、0修改、不可变记录；人工抽查自动接受项是否漏掉错误。override率仅描述人工操作，不当作真实错误率。
- **异常：**异常未处理不继续；写入失败保留原分与状态，明确重试；reveal不改分、不把映射提前发客户端。
- **现状：**复核与审计已有；自动接受规则的漏检/误报验证待补。来源：[复核服务](../../lib/services/human-review.service.ts)、[快速推进](../../lib/services/quick-evaluation.service.ts)。

## N07 Findings 提炼与人工确认

- **AI任务：**`findings`。
- **目标：**把实测证据提炼为可观察发现与使用影响，由人确认后进入写作。
- **输入：**已揭盲上下文、Research背景、Locked Plan、TestRun与可读取证据；Research不覆盖实测结果。
- **输出：**summary、1–12个findings和limitations；每项有产品/Case/Artifact引用、observation、impact与confidence。保存AI原稿及人工确认后的有效版本。
- **验收：**引用属于当前任务与产品；观察与影响分开，不把单样本扩大成普遍成功率，不用工具失败归因产品缺陷；未确认不得写作。
- **评测：**人工逐项标支持/矛盾/无法核验，检查观察完整性、影响解释与范围。记录修改/删除原因，但确认率不等于事实正确率。
- **异常：**原始证据不足先失败或补材料，不为满足当前至少1条的Schema编造发现；重新生成保留旧版本。
- **现状：**引用与人工确认已有；语义支持和遗漏统计待补。来源：[Findings服务](../../lib/services/findings.service.ts)、[输出Schema](../../lib/ai/schemas/findings.schemas.ts)。

## N08 选题与 Story Brief

- **AI任务：**`content_discovery`。
- **目标：**选择对读者有用且证据充足的主线，写作前确定能说什么与不能说什么。
- **输入：**已确认Findings，或专业来源投影出的观察；所选任务、产品背景、实际证据与写作配置。正文不把完整Report或数值排名当母稿。
- **输出：**候选选题、选中角度及Story Brief；Brief含readerQuestion、targetReader、spine、supportingPoints、scope、ending、avoidClaims等。
- **验收：**每个观点对应给定事实和真实Artifact；比较必须有共同任务，缺少主线证据不写；不能让显眼小问题压过核心结果，不能把候选角度当必须证明的结论。
- **评测：**人工按读者问题是否明确、证据是否足够、主次是否合理、边界是否恰当进行评价，并记录被拒选题原因。
- **异常：**引用无效或材料不足停止/补材料；不靠增加虚构细节凑文章。当前Schema要求1–6个候选，与规范允许0个有差异，需单独核对后续产品修正，不能声称0候选已完整实现。
- **现状：**选题与Brief已有；选题不足处理存在上述规范差异；统一选材评估待补。来源：[生成服务](../../lib/services/publish.service.ts)、[选题与Brief Schema](../../lib/ai/schemas/publish.schemas.ts)。

## N09 初稿生成

- **AI任务：**`community_post`。
- **目标：**用具体细节回答一个读者问题，形成可核验的标题与正文。
- **输入：**Brief、factLedger、原始文本/可用视觉细节、渠道和篇幅配置；任务要求与角色经历标明为材料，不当作者亲历。
- **输出：**title、body、tags、interactionQuestion；内部分数、引用ID和选题元数据由程序处理，不让写作者复写来源关系。
- **验收：**遵守Schema与现有渠道规则；标题具体且包含产品；不虚构经历、数字或未测收益；材料少允许短，不靠固定段数凑篇幅。
- **评测：**固定Brief比较写作模型/Prompt；人工分别看事实有据、回答问题、具体细节、表达和编辑负担，最终采用还要经过后续审核。
- **异常：**结构问题同Provider有界修复；草稿状态不当成合格成稿。缺核心材料返回错误或交由上游补足，不编造。
- **现状：**四字段写作与程序规则已有；固定数据集质量/成本对照待补。来源：[生成服务](../../lib/services/publish.service.ts)、[写作规则](../../lib/community-story-policy.ts)。

## N10 只读初审

- **AI任务：**`community_post_evidence_check_text`、`community_post_evidence_check`。
- **目标：**检查初稿的事实、范围、主次和表达，给出可定位、可执行的问题；不替换文章。
- **输入：**实际初稿、Brief、事实与原始证据；路由按实际内容是否需要视觉选择。
- **输出：**articleReview四项质量判断及issues；问题包含field、quote或null、kind、reason和instruction。
- **验收：**非空quote必须逐字属于当前稿；审核不通过必须有具体问题；程序规则发现的问题同样进入修订依据。模型布尔通过不当作独立人工通过。
- **评测：**使用人工标注的正常稿和错误稿，测漏检、误杀、问题定位准确性与建议可执行性，不能只测故意造错的负例。
- **异常：**Schema问题有限修复；事实/表达问题按当前流程进入一次受限修订，再独立最终核验。不要沿用旧版“一切事实问题均立即终止”的描述。
- **现状：**只读初审与定位校验已有；审核器独立校准待补。来源：[生成服务](../../lib/services/publish.service.ts)、[审核Schema](../../lib/ai/schemas/publish.schemas.ts)。

## N11 按问题定向修订

- **AI任务：**`community_post_humanize`。
- **目标：**只解决初审与程序规则指出的问题，保留无问题内容。
- **输入：**原稿、问题清单、同一写作材料与Brief；没有需要解决的问题时跳过此节点。
- **输出：**只返回title、body、interactionQuestion；标签、事实和证据引用等受保护元数据由服务端保留。
- **验收：**严格三字段，不越权修改材料；有问题却返回完全相同内容会失败；修改事实只能纠正有依据的问题，不能创造新结果。
- **评测：**人工比较问题修复率、新引入错误率和无关改动；“变了字”不等于修好了问题。与无条件整体改写可作离线方案对照。
- **异常：**只做一次业务修订；结构修复与业务改写次数分开。失败明确停止，不能回退未核验草稿或无限循环改到放行。
- **现状：**按需三字段修订已有；修复率与副作用统计待补。来源：[生成服务](../../lib/services/publish.service.ts)、[修订规则](../../lib/community-story-policy.ts)。

## N12 最终只读审核与版本保存

- **AI任务：**`community_post_evidence_check_text`、`community_post_evidence_check`。
- **目标：**审核将实际保存的最终全文，确认问题已解决、含义有据且图片关联正确。
- **输入：**最终稿、原稿、初审问题、Brief、原始Artifact；原稿仅用于修订对照，不强制保留其错误。
- **输出：**articleReview、六项stylePreservation与可选截图推荐；程序合并已审文案，保存新的PublishPack与generationTrace。
- **验收：**最终审核不返回新正文；质量和保真任一不通过不得ready。只用真实图片和最终正文对应片段；无效可选推荐可过滤，不能把视频或PDF伪装图片。
- **评测：**独立人工抽查实际保存稿；计算最终误放行、修订新增错误及审核对象/保存稿一致性，分开统计初稿和成稿，避免只看幸存成功稿。
- **异常：**语义拒绝不能靠同稿反复抽审随机过关；保存响应丢失按版本与签名确认，失败保留历史，不覆盖旧成稿。
- **现状：**审核、门禁与版本保存已有；独立人工漏检统计待补。来源：[生成服务](../../lib/services/publish.service.ts)、[最终审核Schema](../../lib/ai/schemas/publish.schemas.ts)。

## N13 人工编辑与采用反馈

- **AI任务：**无必选任务；用户显式换标题使用`community_post_title`，显式重生成复用写作链路。
- **目标：**用户决定是否采用，保留编辑结果与真实生产负担；实际发帖由人完成。
- **输入：**已完成文章、原始材料、人工修改和采用/拒绝原因。
- **输出：**现有人工保存的新版本与manualEdit/aiReviewed=false；建议新增独立采用记录，含最终版本、修改工时、采用结果、原因与人工费用口径。
- **验收：**人工编辑不继承旧稿AI审核徽章；旧版本保留；图片仍来自真实Artifact。复制、保存ready或公开可读都不等于被编辑采用或已发布。
- **评测：**按生产任务统计采用率、编辑工时与综合成本；抽查人工编辑后的事实风险。采用记录须绑定具体版本，不把后续人工改稿效果归给AI初稿。
- **异常：**过期版本拒绝覆盖，保存失败保留输入；采用事件的去重/撤销口径待设计，不借写作版本日志推断用户行为。
- **现状：**编辑与新版本已有；统一采用反馈、工时和费用记录是待补设计。来源：[生成服务](../../lib/services/publish.service.ts)、[产品规范](../../PRODUCT_SPEC.md)。

## N14 专业结果分析与报告支线

- **AI任务：**`result_analysis`、`report`。
- **目标：**解释已锁定的最终评分，组织可追溯的专业报告；不改变最终分与排名。
- **输入：**已揭盲的Final Scores、签名、Rubric、Case、证据、人工审计与产品身份。
- **输出：**ResultAnalysis与绑定它的Report，保留方法、发现、建议、限制与原始证据关系。
- **验收：**分数/排名由既定数据确定；分析签名与当前分一致；报告只组织表达。快速路径不能因专业报告失败丢掉已有Findings或文章。
- **评测：**程序比较数值/版本/排名；人工检查解释是否有据、建议是否符合任务范围，不把综合冠军写成所有人的唯一选择。
- **异常：**签名不一致标记stale并生成新版本；失败独立重试，不改历史评分或用旧分析冒充新分析。
- **现状：**专业分析与报告已有；解释质量、人群建议和事实支持的统一评估待补。来源：[分析服务](../../lib/services/result-analysis.service.ts)、[报告服务](../../lib/services/report.service.ts)。

## 节点展示示例 待验证的设计练习

用合成练习说明输入输出和评分，不能当项目真实成果：

- 原始任务要求“生成30秒视频”；文件元数据为48秒，抽样帧仅覆盖部分画面；ASR不可用。
- Findings可写实际时长与采样帧观察，不能写“成功生成30秒”“全片动画流畅”或“没有配音”。
- 写作若出现这些说法，标注相应证据与范围问题；修订只能改成实际支持的判断，最终审核检查实际稿。
- 该练习帮助定义规则；真实评测须用冻结的原始文件、实际观察与人工标注，不能把合成练习数字当历史样本结果。

以N10为例，假设初稿中出现“已成功生成30秒视频”，审核输出可按现有Schema表达为：

```json
{
  "articleReview": {
    "concreteScenes": true,
    "boundedInterpretation": false,
    "nonRepetitive": true,
    "usefulConclusion": true,
    "issues": ["把任务要求的时长写成了已达成的结果"]
  },
  "issues": [{
    "field": "body",
    "quote": "已成功生成30秒视频",
    "kind": "fact",
    "reason": "任务要求为30秒，但给定文件元数据为48秒",
    "instruction": "依据实际时长纠正句子；不补写未经观察的画面或声音结论"
  }]
}
```

程序再验证quote确实属于当前初稿，N11只修订允许的文案字段，N12对实际最终稿独立核对。人工离线标注用于检查这条问题是否判断正确；这个JSON本身不是实测输出。
