# AI Benchmark Studio 提示词重构最终目标

更新日期：2026-10-09

## 任务

请结合项目流程和当前全部生产提示词，重新设计这套项目的提示词体系。

可以重新思考：

- 现有阶段是否合理
- 每个阶段应该负责什么
- 哪些提示词应当合并或拆分
- 不同阶段应该传递什么信息
- 什么内容应该由模型完成
- 什么内容更适合由程序检查
- 最终文章应该怎样从测试材料中产生

不需要沿用当前提示词的表达方式，也不需要默认当前生成链路就是最佳方案。

## 最终内容目标

项目最终需要生成适合小红书、AI 产品社区和社交平台阅读的内容。

理想文章应该做到：

### 1. 从读者的问题出发

文章先回答读者真正想知道的事情，例如：

- 这个产品能解决什么问题
- 在什么场景下好用
- 实际效果怎么样
- 有什么明显限制
- 适合谁使用
- 是否值得尝试

文章不应只是把测试报告重新排版。

### 2. 有清晰的主线

一篇文章围绕一个最值得讨论的问题展开。重要发现得到充分解释，小问题保持合适的篇幅，不因为更显眼就成为全文中心。

### 3. 标题清楚、有真实吸引力

标题应让读者知道文章在讲什么，并通过真实结果、场景、反差或使用边界产生兴趣。

标题不应像测试项、Bug 工单或内部结论标签。

### 4. 使用具体细节

文章应尽量呈现真实任务、产品输出、关键原句、画面细节、数字和操作结果，让读者能理解判断是怎么得出的。

避免只写“整体不错”“内容完整”“功能很好”等抽象评价。

### 5. 结论与证据的分量一致

文章的正负判断、篇幅和语气，应与实际证据的重要程度一致。

一次小摩擦不能被放大成产品完全不好用；一次成功也不能被扩大成产品在所有场景都可靠。

### 6. 自然地说明边界

如果本次只测试了一个场景，可以自然说明覆盖范围，但不要把测试不足写成产品缺点，也不要反复使用报告式免责措辞。

### 7. 给出明确结论

文章结束时，应让读者知道这款产品在本次场景中的实际价值、适合人群和使用限制。

互动问题可以有，也可以没有，不需要每篇强制添加。

### 8. 像真实作者写作

语言应自然、具体、有判断，避免：

- “好用的：”“一般：”“难用的：”等机械分类
- 测试维度和报告术语
- 固定开头和固定结尾
- 同一结论反复改写
- 为了篇幅补充空话
- 没有依据的个人情绪和使用经历

材料少时允许写成短内容，材料丰富时再展开。

### 9. 保持事实可信

文章中的产品行为、数字、引用和体验判断应来自实际测试材料。

产品没有被测试的能力可以作为下一步值得验证的问题，但不能被写成已经发生的事实。模型的解释和推断应与直接观察区分。

### 10. 图片真正支持正文

如果测试材料中有能够说明问题的真实截图，文章应能选择并对应到相关段落。图片用于帮助读者理解证据，而不是装饰或凑数量。

## 希望得到的结果

请输出一套新的提示词设计，包括：

1. 对当前提示词和生成链路的整体判断
2. 建议的新生成链路
3. 每个阶段的目标和输入输出
4. 每个阶段的新版提示词
5. 建议保留、删除或合并的旧提示词
6. 如何评价新版提示词是否比旧版更好

请优先追求整体内容质量。提示词应给模型足够的理解和判断空间，同时让最终文章保持真实、具体、自然和有价值。
