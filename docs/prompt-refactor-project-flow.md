# AI Benchmark Studio 项目流程

更新日期：2026-10-11

## 项目定位

AI Benchmark Studio 用真实测试材料评估 AI 产品，并把测试中值得讨论的发现转化为社区内容。

核心路径是：

```text
研究产品
→ 设计测试
→ 人工真实体验
→ 收集原始结果
→ 分析发现
→ 形成观点
→ 生成文章
```

## 完整流程

### 1. 创建测评

用户输入项目名称、测评意图，以及 1–3 个产品。项目既可以体验单个产品，也可以比较多个产品。

### 2. 产品调研

系统检索产品官网、文档、帮助中心、价格和使用限制，再整理产品定位、目标用户、核心能力、主要功能和输入输出限制。

如果是多个产品，还会判断它们是否适合在同一条件下比较，以及共同可测试的能力是什么。

### 3. 生成测试方案

系统根据测评意图和产品调研生成真实测试任务，包括：

- 测试目标
- 给产品使用的 Prompt
- 需要的输入材料
- 希望保留的结果证据
- 评价维度

快速模式生成一个最有代表性的任务；专业模式生成多个任务。用户确认方案后锁定，避免看到结果后再改变评价标准。

### 4. 人工执行测试

用户亲自进入被测产品，按照同一测试方案执行任务，然后上传产品的原始输出。

原始结果可以是文本、图片、PDF、Office 文件或视频。它们是后续分析和写作的事实来源。

### 5. 匿名分析与人工确认

系统隐藏产品身份，用统一标准分析原始结果。完成评分后，用户可以复核异常结果，再揭晓产品身份。

系统随后从原始结果中整理体验发现，例如：

- 哪些能力实际有效
- 哪些地方表现一般
- 哪些地方难用或失败
- 这些表现对使用者意味着什么
- 本次测试覆盖到哪里

用户可以确认或修改这些发现。

### 6. 发现内容选题

系统根据已经确认的发现，判断哪些内容值得写成社区文章，并形成候选角度。

选题应围绕一个读者真正关心的问题，而不是把所有测试结果都塞进一篇文章。

### 7. 生成社区内容

当前内容链路是：

```text
视频先读取具体细节
→ 围绕读者问题规划 Story Brief
→ 带入原始细节写初稿
→ 只读核对内容和证据
→ 有问题才定向修订
→ 独立检查最终事实与表达
→ 保存文章
```

文章完成后，用户可以在不修改正文的情况下单独刷新标题。

### 8. 专业结果与报告

专业模式还会根据最终评分、测试任务和证据生成完整结果分析与深度报告。

深度报告用于完整呈现测评过程；社区文章用于讲清一个值得讨论的问题。二者服务于不同阅读目的。

## 快速模式

快速模式由后端自动推进：

```text
自动调研和生成方案
→ 用户采用方案
→ 用户执行测试并上传结果
→ 自动分析
→ 用户确认发现
→ 自动生成文章
```

用户不需要在每个 AI 阶段点击按钮。流程只在需要用户判断或提供真实材料时暂停。

## 这套流程产生的主要材料

```text
Product Research
Test Protocol
Test Case
Raw Artifact
Judge Result
Human Review
Experience Findings
Content Idea
Community Post
Final Result Analysis
Deep Report
```

最终文章建立在前面的真实测试材料上，但不应该把这些内部步骤和术语直接写给普通读者。
