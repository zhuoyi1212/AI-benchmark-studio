# 重新生成失败排查 · 2026-10-16

本次从线上已保存的任务、文章版本及模型阶段输出定位问题，未重新发送现有项目材料给模型。

## 已确认原因

### 旧任务处理了新版本

腾讯元宝项目 `85cc4ea9-9902-4e10-aacc-e2320cbac926`：

- 10月16日11:02 UTC创建v5重新生成任务，11:02:49保存策划结果。
- 10月14日创建的旧普通写作任务仍绑定v1，却在10月16日11:03–11:05执行初稿、初审、修订和终审，操作了当前v5。
- v5被标记失败后，新任务报“重新生成记录无效”。旧任务再次运行还创建了v6，并复用了自己的失败终审结果。

旧恢复查询的`id=原版本 OR created_at>=旧任务创建时间`覆盖了更新版本；普通写作又按“当前最新文章”继续，而非严格使用任务目标。

修复：执行及重试入口拒绝已被新写作请求替代的旧任务；worker在恢复前检查目标版本；普通写作与显式重新生成都绑定目标packId。当前失败版本的合法重试创建新版本，并在模型执行前用有效lease持久化新目标。Publish不再按时间批量标记中断。页面不再由旧任务错误覆盖新版本编辑器。

### 终审混淆策划与最终正文

腾讯元宝终审批评“可核对后引用”，但这句话只在策划稿ending中，未出现在最终正文。终审六项保真及四项质量均为true，却在issues中留下这一意见，导致整篇失败。

修复：新终审契约要求每条阻断理由都有field、最终稿逐字quote、kind、reason、instruction。理由必须与质量/保真问题对应；结构缺失之外不能使用空引文。格式或定位不正确仍走同Provider最多两次的既有修复；实际内容错误继续失败，不能自动放行。用户可看到具体未解决原因。

### 修订未真正解决确定性问题

即梦历史失败稿把“这轮不用重写文案”换成“这轮内容本身不用改”，仍是未获直接支持的收益断言；旧标题失败记录也显示修订后仍可能超过28字。

修复：定向修订返回时立即执行标题、无依据断言和已知机制推断校验；不合格返回使用既有同Provider校验修复预算，不增加无限写作循环。最终独立审核和保存前门禁继续执行。

### 表达规则误拦截

懂你AI历史记录因“容易踩的坑”被泛化的“容易”关键词规则拦截。该词组描述话题，并不声称观察到某种行为频率。

修复：确定性规则聚焦“容易出错/失败”等具体行为表达；其他事实、收益、频率与百分比继续由原有规则和两次证据审核校验。

## 边界与验证

不修改历史实验、AI评分、已确认Findings或原有ready文章；不改变Blind、人工测试、Human Review与Storage规则。本次没有新增表或migration，沿用`quick_jobs`、`quick_job_steps`、`publish_packs`及原Provider路由，只升级修订/审核Prompt与运行时校验。

验证结果见PLAN.md当日Progress Log。自动测试与模拟模型E2E只证明已覆盖的程序行为，不能代替真实多项目生成成功率、审稿准确率或自然度评测。后续真实回归应分项目记录生成成功、误拦截、漏检、调用成本和人工采用结果。
