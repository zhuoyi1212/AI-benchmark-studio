# 页面响应与报告排版修复（2026-10-01）

## 原因与改动

- 动态路由缺少 loading 边界，点击后旧页面停留到数据库链读完。补齐快速工作台、结果、报告、发布页的占位；导航链接立即显示 pending，快速操作按钮显示提交中；数据库读取失败提供重试入口。
- Research → Protocol 原本串行读不相关数据。改为并行；同一服务端页面渲染内合并相同 GET，保留全部结果新鲜度、协议、Blind 和评分校验。作用域不跨页面、访客、刷新、Server Action 或 worker；写入、带显式取消信号/业务超时的请求不复用，失败不缓存。
- 上传完成检查原本两次重建整个测试工作区，包括调研及所有证据签名。改为一次读取当前锁定协议、测试行与持久化证据；后端仍负责完整测试矩阵和 Blind 校验。不存在、归档、专业项目、过期协议或缺少证据不会误投递快速评分。
- 最近项目中的快速项目直接回到 `/quick`。
- 真实与 demo 报告标题由桌面 48px 调整为 28px 加粗，手机 24px。目录与测试快照合并在 208px 左栏，正文使用剩余宽度，间距 32px。单产品场景卡片占满正文宽度；报告生成状态自动刷新。

## 实测

同一真实报告，本地 Next dev、后端 worker 关闭、只读。首轮曾出现 Supabase 域名 ENOTFOUND，约 7 秒后失败，随后恢复；该网络问题独立于应用优化。

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 两次热请求完整响应 | 5.87s / 4.38s | 2.92s / 2.76s |
| 页面作用域内实际 GET | 40 | 37（复用 3 次） |
| 点击导航反馈 | 缺少提示 | 实际观察到“正在打开页面” |
| 1280px 视口 | 标题 48px，右栏易被挤压 | 标题 28px，侧栏 208px，正文 712px |
| 390px 视口 | — | 标题 24px、快照折为单列，无页面横向溢出 |

这是开发机上的少量测量，不能当作稳定性能 SLA；AI 生成时间及外部数据库延迟仍存在。诊断可设置 `LOG_PAGE_READS=1` 查看无敏感内容的计数，`PAGE_READ_DEDUPE_DISABLED=1` 可关闭复用以对照。

## 验证与边界

- 235 项测试，新增覆盖渲染隔离、并行读取、身份 header 隔离、写操作/取消、失败重试，以及快速上传就绪与协议版本检查。
- typecheck、生产 build、diff check。
- 浏览器验证真实报告桌面/手机、报告到结果页的点击反馈和完成状态，无控制台错误。
- 完整 DB/Storage E2E 通过：创建→调研→方案→上传→Findings→确认→发布→专业评分/分析/报告，含真实页面读回、图片 Judge、可比/不可比分支；3/3 临时项目已归档。首轮在创建测试项目时失败且未创建项目，连接恢复后重试通过。
- 没有 migration、密钥、AI prompt、AI Score、Human Review 事件或历史报告内容变更；真实页面没有 Mock 回退。E2E 使用显式隔离 fixture 与模拟 AI。
- 当前增量不重做 M0–M15，也不声称重新认证所有产品 Acceptance Criteria；未发布线上。
