# 默认生成风格

用户选中即梦新图对照的第二版。后续默认使用task-led-review/1.0.0，基于原候选卡的表达规则；不是微调模型或已验证的质量提升。

- 策划、初稿、定向修订各携带一次固定规则，保留de-ai-flavor及事实契约。
- 审核继续只读核查，既有经历、数字、引文、范围门禁不变。
- 标题表达完整，将具体动作概括为本次用途下的表现；“元素都在下半”改为“布局符合指令”，不扩成普遍能力。
- 标题编辑、初稿、修订和两次审稿共享标题规则；不为了标题结论修改正文事实。

代码在`lib/community-task-led-style.ts`与`lib/community-title-policy.ts`。策略升为`community-story.v14-task-led-review`，六条受影响路由Prompt升版；模型、调用阶段、JSON、来源和历史版本保持。固定规则实际内容进入消息签名，不依赖全局Skill目录或研究JSON的运行时开关。

本地[采用稿](project-articles/2026-10-26即梦新图两版对照/采用稿.md)使用新标题，正文与原第二版逐字相同。新标题是明确的人工编辑，不冒充模型输出或新的AI审核；原有作者场景问题仍保留记录。旧对照不改，旧实验重放入口拒绝在新基线上继续运行，避免重复追加风格卡。

本地接入阶段未调用付费模型或部署。用户随后授权上线，现已[发布新规则](releases/2026-10-26-task-led-review-titles.md)，仅作用于后续生成；已有文章保留。
