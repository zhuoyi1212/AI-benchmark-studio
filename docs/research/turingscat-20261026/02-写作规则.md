# 测评文章写作规则

这是一版基于10条视频可读AI字幕的分析候选，未接入生产，也未用新稿盲评验证自然度。视频和定位依据见[阅读笔记](01-视频笔记.md)，结构化规则见[writing-rules.json](writing-rules.json)。

最有用的迁移是：**围绕一个实际问题，选择具体操作和结果，解释它为什么影响判断。** 不要求固定段落顺序。

| 规则 | 写作时怎么做 | 来源 |
|---|---|---|
| R01 使用问题 | 交代产品、任务和值得观察的一点；也可以直接给出有据结果。 | S01、S04、S08 |
| R02 过程推进 | 输入或动作带来结果，新问题再带来下一步；仅采用真实记录。 | S04、S06、S09 |
| R03 细节支持评价 | 说明哪一个具体细节，让这次任务更方便、更困难或更可信。 | S05、S08、S09 |
| R04 判断有来由 | 真实记录有预期变化才写转折，否则直接呈现判断。 | S02、S03 |
| R05 技术有用途 | 先说明体验问题，再讲必要技术；实测、资料与推测分开。 | S03、S05、S07 |
| R06 篇幅有主次 | 重点展开会影响选择的差异，普通达标项可合并。 | S01、S09、S10 |
| R07 结论有范围 | 写清影响判断的条件；一次结果不外推长期表现。 | S01、S02、S03、S06、S07、S08、S10 |
| R08 口语有对象 | 普通词、具体动作和有依据的态度，比堆语气词更有用。 | S04、S05 |

这些是对样本的解释与项目适配，不是通过统计证明的因果规律。不同视频的叙述差异很大，不应归纳为所有文章必须采用的单一模板。

## 不直接继承的部分

- **宏观收尾。** 样本有行业、未来和价值层面的收尾；短文可以在具体问题回答清楚后结束。这是项目编辑建议。
- **产品背书与技术猜测。** 学习表达组织，不把旧视频评价、参数或推测带入新文章。
- **先怀疑再惊喜的剧情。** 只有真实作者材料支持时使用，避免所有产品都演一次反转。
- **第一人称经历。** 博主的养猫、创业、投资、购机和使用体验不能变成你的经历。你可以表达自己提供的关注点与取舍。

## 改写示例

以下是我编写的教学示例，不是视频原文，也不是新增真实实测。假设材料只明确记录：一次无参考图海报生成，标题和时间准确，指定元素放在要求的位置；作者最在意信息准确，不打算评价其他用途。

生硬写法：

> 文字方面符合要求，布局方面符合要求，整体体现了较强的指令遵循能力，建议用户结合自己的实际情况进行选择。

可用写法：

> 这张活动海报最关键的两处信息，标题和时间，都写对了。指定的元素也放在要求的位置，这次没有出现信息写对、布局跑偏的问题。
>
> 对这张海报，我更看重信息能不能准确传达。就这次结果看，这一点做到了。

改写增加了评价的着眼点，没有补写担心、惊喜、发布效果或后续使用。实际生成时，第二段的关注点必须来自作者输入。

## 怎么验证是否真的更自然

先在独立测试中应用[提示词](03-可直接使用的提示词.txt)，不要直接改线上规则。选6份真实材料，保留原提示词与原稿，用相同材料、模型和输出预算生成新版；隐藏版本标签后请读者比较：更愿意读哪篇、依据是否清楚、哪里仍像模板。事实错误单独记录，不能用自然度抵消。

每份材料只形成一次配对比较；不靠重复抽稿挑出最好的一版。记录偏好和理由，再决定哪些规则进入现有写作与审核流程。本轮完成的是语料分析与规则候选，尚未开展这项效果实验。
