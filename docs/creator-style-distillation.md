# 从测评视频文本提炼可复用风格

2026-10-26已收到图灵的猫10条视频的来源关联分析包，原样导入[研究目录](research/turingscat-20261026/README.md)。它不含逐字转写；本轮据此整理了[候选风格卡](research/turingscat-20261026/05-候选风格卡.md)及[本地配对方案](research/turingscat-20261026/06-对照评测方案.md)。规则指导叙事与选材，常用词、句长和口头禅仍未知；没有宣称效果提升或运行时启用。下方JSON仅说明字段，不代表已上线配置。

先做“语料分析 → 风格卡 → 少量对照例句 → 提示词应用”。这个阶段不训练模型参数；等素材充分、有稳定人工评价且提示词方案仍有明确瓶颈，再决定是否需要微调。

## 需要的材料

先准备同一博主约6–10篇完整测评转写稿，覆盖喜欢、不满意、一般、有取舍的不同评价；不要只有开场或全是同一产品。另留2–3篇完整视频不参与提炼，用来检查总结的规则能否解释新稿。数量是起步建议，不是统计保证。

每份保留文件名/来源链接、完整段落，最好有时间戳；标出用户特别喜欢和不喜欢的段落。先校对ASR错字和产品名，清理重复字幕、广告、赞助话术、求关注及视频指路。停顿、转折和有效口语保留；“呃/那个”与字幕断行不能直接当文章风格。

## 把事实、经历和语言拆开

| 内容 | 提炼去向 | 不可误用 |
| --- | --- | --- |
| 怎么开头、哪里转折、句子长短、评价放在哪里 | 风格卡 | 不把单篇习惯硬化成每篇固定模板 |
| “我很意外”、盯图、重试、和客户沟通 | 只作为作者经历识别，不迁移 | 不冒充本项目作者的反应/过程 |
| 产品名、版本、价格、次数、效果和技术解释 | 原视频内容的事实栏，写作时不传入本项目事实账本 | 不给当前产品背书，不从措辞推断已测效果 |
| 独特口头禅、夸张词、引流句 | 标记是否适合文字，不默认保留 | 不靠复制口头禅代替风格 |

每个风格判断要附2–3处不同稿件中的短片段及来源定位，并找反例：何时他反而会用步骤/长句/正式词。找不到跨稿依据的规则先标“候选”，不能由一段强行总结人格或职业。

## 风格卡字段

```json
{
  "id": "待语料到齐后命名",
  "version": 1,
  "status": "template_only",
  "sourceIds": [],
  "opening": "从什么信息切入；允许哪些变化",
  "progression": "结果、例子、取舍如何连接；哪些情况用步骤",
  "cadence": "长短句、段落长度与停顿习惯",
  "vocabulary": "常用日常动词、应保留的技术名词、避免的空话",
  "judgment": "评价如何贴着证据出现；如何表达保留意见",
  "emotion": "真实反应的语气与密度；无记录时如何写",
  "ending": "什么情况下直接结束，什么情况下给建议",
  "evidence": [],
  "counterexamples": [],
  "transferExamples": []
}
```

候选规则：“判断紧跟具体细节，不在每段末尾重复总结；重要问题多写，普通达成项可以并在一句。”与本次用户要求一致，也见所附研究R03/R06的跨篇分析；仍不是逐字语料的统计特征。

## 应用到本产品

`当前任务及真实证据 → Story Brief → 风格卡＋少量对照例句指导初稿 → de-ai-flavor编辑检查/定点修订 → 原始证据独立终审 → 新文章版本`

风格卡只控制怎么说。当前事实账本控制发生了什么，作者判断控制真实关注点与感受，两者都不能被风格卡覆盖。参考范例应是合成或已核实事实的“报告体 → 自然表达”短对照，不把博主整篇测评或跨产品数字塞进正文模型。

产品接入时用结构化、可版本化的服务端profile；写作和修订携带同一profile，审核能检查是否因风格引入新事实，profile版本和实际内容参与签名与审计。用户选择profile应随新PublishPack保存；旧稿/旧配置不覆盖。未指定时继续普通社区风格。不要从任意本地路径或外部网页动态加载指令。

通用de-ai-flavor已在前一任务接入本地代码。本轮新增task-led-review / 0.1.0-candidate结构化候选卡及来源定位，runtime_enabled=false；没有增加自动蒸馏、选择器、微调或运行时加载。七份原文件有导入哈希，原研究的现场核验结论属于原记录，本轮只复核文件与关联。

## 看实际样稿再迭代

当前Skill已经进入基线。本轮方案在同一批未用于例句的真实项目材料上比较A当前Skill链路、B当前链路加候选卡，保持模型、事实输入和篇幅要求一致；不额外拆成三个版本。随机打乱顺序，比较自然程度、是否有明确判断、是否重复、需要多少人工修改；另查虚构经历、数字/来源漂移和遗漏条件。不能用“AI味百分比下降”替代读者采用与事实核对。

至少包含材料少、主要正面、主要负面、有真实反应、没有作者输入、文字与图像任务。用新主题检验能否迁移，而不是只在原博主讲过的产品上像。保留失败、人工意见和版本，修改规则后再用留出材料验证。
