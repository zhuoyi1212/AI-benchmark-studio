# Publish 原文约束与失败恢复

本次边界仅 Publish；不修改 Research、Protocol、Test、Artifact、Judge、Human Review、Results、Report 或已有 Publish 版本。

## 根因与修复

- 普通 TXT 没有约定的小标题时，旧解析器返回空对象，导致 rawExcerpt 丢失。现在返回 null，保留原文输入；读取仅做有界重试，不生成替代材料。
- Micro Finding 的 rawEvidence 必须是其来源原文的连续摘录；保持数字、算式和来源 ID 绑定。页面外壳文案不能作为模型正文行为的证据。有原文时不接受 Judge 转述冒充原文。
- WritingPacket 携带一条 anchor 原句及最多两条 supporting 原句；正文和 Critic 使用同一个小素材包，仍不传完整 Report。
- 真实模型回答不等于作者亲历。只有经原文核对的作者 user_note 才可启用体验语态。普通回答默认观察语态，可以表达当前观点，不能补“我问/我让/我买/我的真实困境”。
- “给了5家/给出10条”不再被当成评分，同时保留总分、维度分、评分和排名禁用规则，防止数字匹配回溯误报。
- Critic 保留模型分项和风险原始反馈，系统按原阈值计算总分与 Verdict。负面审稿即使只有一项问题也是有效反馈，不要求模型凑三条修改。任何专业门禁失败或事实风险非空仍不得通过。
- Critic 使用既有 Pro route，保留 high reasoning、7000 token 上限。真实回归中 non-thinking 曾误放行无依据事实，已撤销该尝试；正文和一次 Safe Rewrite 仍是 Flash non-thinking，medium 上限 1800 tokens，无默认 Pro 正文兜底。
- 自定义选题可显式绑定已有 anchor，清除无关 supporting 与旧解释；最终素材包不再携带模型扩写的 technicalTruth。后台精确原文继续保留。
- 正文核心观点与内容类型必须匹配素材包；节选不能用于断言整份回答“没有提供”某项信息。初审发现事实风险直接失败，不允许语言润色掩盖事实问题；被拒绝的原稿也不能靠原样复审随机放行。
- 分段和 Evidence Anchor 校验提前进入模型输出 schema，使同一次有界修复能处理格式问题，而非返回后整轮失败。
- Safe Rewrite 或复审不可用时，仅能保留独立审稿通过的原稿；绝不以未审稿的内容兜底。
- 失败状态 RPC 有超时和最多三次幂等重试，持续不可用时显式抛出，不吞掉持久化失败。
- 完成写入若丢失响应，先按版本 ID 回读并核对内容签名；仅精确匹配才确认成功，否则有界重试，读失败不能被当成已提交。
- 选题解释不得把局部引用扩大为全部条目，不得混同不同店铺，不得推测模型动机；模型给出的地址、法规、品牌、续航仍是待核验输出，不作为外部事实背书。

## 验证范围

回归覆盖原文解析、引文数字、页面外壳、私人经历、数字数量、实际 Critic schema/JSON schema、含义复审必填与失败状态重试。真实验证复用原项目现有材料，只调用 Publish 内容任务。具体版本与运行结果见本轮交付记录。

2026-09-08：原项目新 Publish v29 已保存，Flash 正文 → Flash Safe Rewrite → Pro 三类复审通过；人工对照原回答，未发现新增经历或数字。v21–v24 自动通过但人工发现事实问题，保留历史、排除合格成果；不把全部候选选题视为已核实。当前仍需人工复核候选解释，自动校验不承诺捕获全部语义编造。
