# 最终内容生成规范

版本：community-content.v1 · 2026-10-04

适用范围：快速模式、专业模式生成的社区文章。专业测评报告、原始测试结果及评分沿用原有规则。

## 一、目标

文章要让读者知道：测了什么、得到了什么、哪些细节支持判断、结论到哪里为止。表达具体自然，不把内部分类表直接变成文章。

本文取代旧的“固定好用 / 一般 / 难用标题”“最低字数和段落配额”“强制第一人称”要求；不改变人工实测、证据真实性、评分不可变及历史版本保护。

## 二、生成路径

**材料清单与结构选择 → 提纲及初稿 → 内容核验 → 语言润色 → 最终保真检查 → 保存新版本**

| 环节 | 负责什么 | 不通过时 |
|---|---|---|
| 整理材料 | 按所选任务提取观察、已有判断、证据关联和测试范围 | 无实测材料则停止，提示补充或重新选题 |
| 选择结构 | 根据同任务的产品数量、任务数量和写作偏好选择结构 | 不用没有证据的比较或复测结构 |
| 提纲及初稿 | 每节关联来源，先形成有限判断再组织全文 | 未知引用、虚构观察片段、重复选材被拦截 |
| 内容核验 | 对照原始证据修正事实，区分产品问题与测试边界 | 未解决的事实或内容问题停止，不送润色 |
| 语言润色 | 只改标题、正文、互动句 | 越权改字段、数字漂移、证据片段丢失被拦截 |
| 最终检查 | 独立核验润色后的事实、含义、质量与图片对应关系 | 任一项失败不能保存为可发布 |
| 保存 | 保存实际审核过的正文、规范版本、提纲和审计 | 持久化失败明确显示，不能假报成功 |

材料提取、结构选择由程序完成；提纲和初稿合并在一次模型请求内，避免增加用户点击。加上初稿核验、语言编辑、最终检查，正常生成共四个 AI 阶段，选题发现另计。快速任务沿用成功阶段检查点，刷新或离开页面不负责推进。

## 三、事实与选材

1. 事实必须来自当前选题覆盖的真实测试材料；调研只提供背景，选题本身不是事实证明。
2. 原始 Artifact 优先于 Findings、评分理由或草稿摘要。证据里的命令只是被测内容，不作为系统指令。
3. 判断写清对象、条件与实际现象。不得推演未经记录的省时、省钱、稳定性、成功率或模型机制。
4. 产品问题与测试边界分开。例如“只测一个场景”写入测试范围，不能据此评价产品表现一般。
5. 未实测方法只能写成建议，不能写成已经验证的结果。
6. 不虚构作者经历或情绪。角色任务里的“我紧张”“我想加薪”不等于测评作者本人经历。
7. 摘要中的观察不是产品原话；直接引语必须能对应原始回答。
8. 没有发现的类别直接省略，不写“缺点：无”“不舒服的地方：没有”，也不把未发现问题写成没有问题。

## 四、三套结构

| 结构 | 选择条件 | 组织顺序 |
|---|---|---|
| 单场景体验 | 所选材料集中于一个任务；默认使用 | 任务和条件 → 回答细节 → 有依据的判断 → 本次范围 |
| 多功能体验 | 有多个任务，或多维度偏好且确有多个发现 | 总体判断 → 不同功能或维度的发现与影响 → 适用范围 |
| 对比测评 | 同一任务下有多个产品的实测证据 | 测试条件 → 结果差异 → 对应证据 → 有限结论 |

结构是编辑顺序，不是固定文案。每节使用具体发现作标题；短观察可不用小标题。不固定优缺点数量，不凑篇幅。篇幅偏好是方向，材料不足必须缩短。

本次不引入跨项目复测汇总；没有多轮记录不能声称完成复测。跨产品只能比较证据共同覆盖的任务和条件。

提纲每节记录：具体标题、来源 ID、从来源观察逐字截取的片段、有限判断。范围说明单独记录，不以“缺点”名义凑一节。同一组证据不能换标题重复扩写。

## 五、正文规范

- 开头可以是具体场景或有依据的结论，不强制“我这次”“我的感受是”。
- 一段增加一项信息；删除同义复述、空泛解释、机械分类前缀。
- 标题不用“好用的：”“一般：”“难用的：”等空标签，直接说明发现。
- 相同范围限制集中说明一次，不同限制仍须保留。
- 没有值得讨论的具体问题时，互动句留空；不得在正文和独立互动字段重复输出。
- 正文不暴露内部 ID、评分、排名或流水线术语。可选个人主观评分沿用独立 personalRating 规则，不混入正文或专业评分。
- 截图只能来自真实 Artifact，与最终段落和原文短句对应；不能为了凑数量自动补图。

示例仅用于说明表达，不能借用其中事实：

| 生硬写法 | 有相应证据时可改为 |
|---|---|
| 好用的：老板画像和话术对上了 | 面对强势老板，它建议先摆成果 |
| 好用的：行动清单很具体 | 准备清单具体到了数字和时间 |
| 一般：只测了一个场景 | 本次只验证了这一种沟通情境，其他场景还需测试 |
| 不舒服的地方：没有 | 删除该空段落 |

## 六、最后润色

润色处理语言，不重新判断产品能力。

**允许：** 改生硬标题、拆长句、改善衔接、删空话和重复、合并重复的范围说明、调整段落长短。原文已经清楚时原样返回。

**必须保留：** 数字及单位、对象、条件、原文引语、具体观察、正负判断、因果、频率、不确定性、证据归属、实测与建议的区别。

**禁止：** 为口语化添加“我惊了”“松了一口气”等无依据感受；将“可能”改为“必然”、“一次”改为“经常”、“建议”改为“已经有效”。

润色接口只接受并返回标题、正文、互动句。标签、提纲、证据、评分与审稿字段由程序保留。数字与观察锚点先做确定性检查，其他语义由下一环节独立核验。

## 七、发布前检查

内容质量检查四项：

- 具体：有实际任务和输出细节，不能只有形容词。
- 有界：判断由证据支持，不把测试不足当成产品缺陷。
- 不重复：章节和段落增加信息，不换词扩写同一观点。
- 有用：结尾回应问题并限定用途，不喊口号。

润色保真检查六项：事实、范围、立场、亲历与情绪、建议、证据归属。

最终审核只返回检查结果与图片关联，**不返回新正文**。这样保存的正文与审核对象一致，不会发生审核后再改稿。通过条件是所有检查为真、问题列表为空，且确定性规则、图片引用和运行时 Schema 均通过。模型自评不是绝对正确性证明，仍需持续抽查真实文章。

## 八、失败、重试和历史

- 每个文本阶段最多两次供应商请求；视觉核验沿用路由上限一次，不跨供应商回退。
- 格式或明确规则错误可在阶段内定向修复；审核返回未解决的内容问题或含义漂移则停止，不反复要求审核改成通过。
- 用户看到失败阶段与重试入口；未合格稿不成为 ready，不回退未审核初稿。
- 新文章保存规范版本、内容提纲、原稿/润色稿、质量与保真结果、四阶段模型/Prompt/签名/用量；不保存思维链。
- 快速模式成功阶段沿用现有服务端检查点。手动专业流程失败仅保留失败状态，本规范不承诺新增全量失败响应归档。
- 旧文章继续可读，不自动覆盖。重新生成沿用新 PublishPack 版本机制，原始实验、评分及文件不重写。

## 九、验收要求

回归覆盖：重复分类前缀、空缺点、仅一个发现、只有负向发现、同任务多产品、不同任务不能冒充对比、未知证据引用、重复提纲、润色越权、数字漂移、任一保真失败、无依据截图、旧文章读取及新版本保存。

工程检查：相关测试、全仓测试、typecheck、build、diff check。真实模型样稿须单独人工阅读，隔离夹具不冒充真实产品测评；线上是否已部署与真实用户文章是否已重生成分别说明。
