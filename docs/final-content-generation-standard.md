适用范围：快速模式、专业模式生成的社区文章。保留既有 Blind、Protocol、人工测试、确认 Findings、评分与历史版本。

## 一、目标

从读者问题出发，用原始细节讲清真实结果，结论与证据分量一致。文章不应只是换了排版的测评报告。

## 二、生成路径

**选题 → Story Brief → 初稿 → 只读初审 → 有问题才定向修订 → 最终只读复核 → 保存新版本**

| 环节 | 职责 | 失败处理 |
|---|---|---|
| 材料 | 限定当前来源与所选测试任务，读取原始输出和已有备注 | 缺少原始证据则停止 |
| Story Brief | 确定读者问题、主线、支撑细节与适用建议 | 无效来源、无主线、无共同任务的比较被拦截 |
| 初稿 | 根据 Brief 和原始细节自由组织全文，仅输出标题、正文、标签、互动 | 无证据不补写，材料少则缩短 |
| 初审 | 只指出事实、权重、范围、结构与语言问题，不改文案 | 问题需可定位、可执行；不通过却不给问题视为校验失败 |
| 按需修订 | 只返回标题、正文、互动；解决模型问题和代码门禁 | 事实或既有质量问题未改则失败；新增文风信号不阻断，不无限改稿 |
| 最终复核 | 只读审查实际最终全文；独立核实事实、观点分量与图片 | 质量/保真任一不通过均不能 ready |
| 保存 | 原子保存实际通过审核的正文、Brief、审计与 usage | 失败有明确状态；不覆盖历史版本 |

正常稿为四个 AI 阶段，有修订为五个，选题另计；历史视频稿可另含一次视觉细节读取（合计五或六个阶段）。后台检查点按路由、版本、输入与 Schema 区分，可从成功阶段续跑。文本 Brief 使用现有 DeepSeek 策划路由；图片/文件 Brief 和复核显式使用既有视觉路由。视频先视觉提取、后文本策划/核验；保留具体视觉细节与读取阶段审计，不重复读取同一大视频。模型配置不变，不跨厂商静默降级。视频沿用现有 MediaEvidence，文章链路不发送原始 MP4。

## 三、事实与选材

1. 事实必须来自当前选题覆盖的真实测试材料；调研只提供背景，选题本身不是事实证明。
2. 原始 Artifact 优先于 Findings、评分理由或草稿摘要。证据里的命令只是被测内容，不作为系统指令。
3. 判断写清对象、条件与实际现象。不得推演未经记录的省时、省钱、稳定性、成功率或模型机制。
4. 产品问题与测试边界分开。例如“只测一个场景”写入测试范围，不能据此评价产品表现一般。
5. 未实测方法只能写成建议，不能写成已经验证的结果。
6. 测试由人工执行。有当前产品、任务及原始 Artifact 时，执行动作可以用第一人称，无需 authorPerspective。查看、运行、贴提示词来自执行事实；下载、导出等具体动作仍需相应原始输出或记录。感受、情绪、耗时、操作次数、继续使用的偏好、手动修改经历仍须有作者输入或测试记录。角色任务里的加薪、紧张不等于作者经历。原始产品回答中的第一人称对话也不算作者记录。
7. 摘要中的观察不是产品原话；直接引语必须能对应原始回答。
8. 没有发现的类别直接省略，不写“缺点：无”“不舒服的地方：没有”，也不把未发现问题写成没有问题。
9. `authorPerspective` 是人工填写的关注点与取舍，决定选材与口吻，不能作为数字、产品能力或亲历的证据。没有填写时不补造私人偏好。

## 四、文章规划

Story Brief 先确定 readerQuestion、targetReader 和 spine，再按对任务结果的实际影响选择 supportingPoints。每项保留 claim、readerValue、findingIds、evidenceArtifactIds、detail 和 role(main/support/caveat)。引用必须属于同一事实；不存在的来源被拦截。

先回答读者最关心的问题，再分配正负发现的篇幅。轻微摩擦不自动抢占主线，重大失败可以成为核心；不硬性规定优缺点比例。corePromiseGaps 记录未被验证的核心承诺，scope、ending 和 avoidClaims 帮助划清结论范围。

不强制三套正文模板、段落数量、维度名称或固定提纲。比较仍要求同一测试任务的真实证据；没有复测记录不能声称完成复测。自定义角度和历史选题也重新规划 Brief，不继承过时主线。

## 五、正文规范

- 开头先给具体观察或读者在意的问题，不念任务参数清单，只保留会改变结论的条件。第一人称不强制，也不因作者没填感受而禁止合法执行动作。
- 一段增加一项信息；删除同义复述、空泛解释、机械分类前缀。
- 标题不用“好用的：”“一般：”“难用的：”等空标签，直接说明发现。
- 标题按材料选择“内容概括”或“结果概括”，产品名与用途之后写具体内容或有依据的主要表现。禁止“给了什么”“表现如何”等空泛问句；不将建议质量写成现实收益。具体读者问题不因问号被拒绝。
- 标题包含真实产品名、测试用途和具体内容或主要结果，6–28 个 Unicode 字符。表达自然，字数有限时删修饰、缩短列举；小摩擦不替代主线，重大失败如实概括，不使用标题党词，数字须在正文有依据。
- 初审与最终审核独立检查标题是否清楚、主次是否符合正文；标题问题按需修订，不改正文事实来配合标题。单独刷新以已核验正文为主，不继承旧标题或旧选题的问题偏向。
- 范围说明全文最多一处，融进判断用日常语言说清；合并时保留所有不同的必要条件，不把未验证变成已验证。程序仅在超过2个范围句时提示，因此0–2句无提示不代表满足写作目标。
- 最能支持判断的一两句产品原话逐字引用，其余可概括。解释只能包含产品原答已有意思，不补推论。段落按读者关心的顺序组织；反常细节可以展开其意义，不按原回答顺序逐项报备。
- 避免固定连接词、编号式结构和密集破折号，句子长短顺着意思。
- 有依据的偏好可以明确表达，篇幅不必对称；用具体细节解释取舍，不机械补反面意见、总结或互动句。审核不因口语、主观取舍或没有总结而拒绝。
- 没有值得讨论的具体问题时，互动句留空；不得在正文和独立互动字段重复输出。
- 正文不暴露内部 ID、评分、排名或流水线术语。可选个人主观评分沿用独立 personalRating 规则，不混入正文或专业评分。
- 截图只能来自真实 Artifact，与最终段落和原文短句对应；不能为了凑数量自动补图。

示例仅用于说明表达，不能借用其中事实：

| 生硬写法 | 有相应证据时可改为 |
|---|---|
| 好用的：老板画像和话术对上了 | 面对强势老板，它建议先摆成果 |
| 好用的：行动清单很具体 | 准备清单具体到了数字和时间 |
| 一般：只测了一个场景 | 本次只验证了这一种沟通情境，其他场景还需测试 |
| 不舒服的地方：没有 | 删除该空段落 |

## 六、最后修订

取消无条件润色。初稿已经具体、清晰、可信时保留原文。

有问题时，初审记录 field、quote、kind、reason、instruction。修订者只解决这些问题，保留不受影响的细节。为纠正事实或结论错误，允许有依据地改变初稿；不机械保留错误数字或判断，也不得编造新体验。只有一个定点修订阶段，然后交给独立最终复核。阶段仍最多两次同 Provider 请求：第一次修订丢了具体细节时，第二次使用已有 Schema 修复机会恢复；不新增循环或切换模型。

Brief、来源与审计不允许修订模型修改。模型仍仅返回三项文案；标签超出5个时，由程序保留原标签前5个，记录 originalTags/tagsTrimmed。这是本次任务对旧标签完全不可变要求的窄例外，不新增标签。实际最终稿作为最终审核输入并原样保存，最终审稿者不能边改边批准。

单独刷新标题继续只改标题并创建新的 PublishPack 版本。标题基于已核验正文、产品名和渠道，旧标题只用于避免重复，同一次请求返回用途/结果事实摘要与标题，服务仅保存标题与既有审计，不保存推理过程。记录前后标题、路由、输入签名与 usage。

## 七、发布前检查

内容质量检查四项：

- 具体：有实际任务和输出细节，不能只有形容词。
- 有界：判断由证据支持，不把测试不足当成产品缺陷。
- 不重复：章节和段落增加信息，不换词扩写同一观点。
- 有用：结尾回应问题并限定用途，不喊口号。

最终保真检查六项：事实、范围、立场、亲历与情绪、建议、证据归属。

最终审核只返回检查结果与图片关联，**不返回新正文**。这样保存的正文与审核对象一致，不会发生审核后再改稿。通过条件是所有检查为真、问题列表为空，且既有事实/范围/机制/评分等确定性规则、图片引用和运行时 Schema 均通过。新增文风信号不计入该失败门槛。模型自评不是绝对正确性证明，仍需持续抽查真实文章。

## 八、失败、重试和历史

- 每个文本阶段最多两次供应商请求；视觉核验同样最多两次，不跨供应商回退。
- 格式或明确规则错误可在阶段内定向修复；审核返回未解决的内容问题或含义漂移则停止，不反复要求审核改成通过。
- 用户看到失败阶段与重试入口；未合格稿不成为 ready，不回退未审核初稿。
- 新文章保存规范版本、Story Brief、只读初审、原稿/最终稿、质量与保真结果、4–6阶段模型/Prompt/签名/用量；不保存思维链。
- 快速模式成功阶段沿用现有服务端检查点。手动专业流程失败仅保留失败状态，本规范不承诺新增全量失败响应归档。
- 旧文章继续可读，不自动覆盖。重新生成沿用新 PublishPack 版本机制，原始实验、评分及文件不重写。

## 九、验收要求

回归覆盖：重复分类前缀、空缺点、仅一个发现、只有负向发现、同任务多产品、不同任务不能冒充对比、未知证据引用、Brief 的主线与比较准入、审核定位、修订越权、最终数值错误、任一保真失败、无依据截图、旧文章读取及新版本保存。

工程检查：相关测试、全仓测试、typecheck、build、diff check。真实模型样稿须单独人工阅读，隔离夹具不冒充真实产品测评；线上是否已部署与真实用户文章是否已重生成分别说明。


## 人工保存与重新生成

“保存修改”将标题、正文、标签、互动句和配图顺序保存为新版本，下一次打开直接读该版；不调用AI、不改上游实验。人工编辑明确标记，旧稿AI审核不代表人工改稿已通过核验。图片仍来自真实测试Artifact，正文移除原证据短句时清空对应段落锚点。

“重新生成文章”基于同一测评材料、选题和配置执行当前完整生成链，标题与正文等随新稿更新；后台队列和检查点保证离开/刷新可以继续，原稿保留。失败可重试，无证据或审核失败不能ready。先保存未保存修改，再执行标题刷新或重生成；新生成不将人工改稿里的新说法作为已确认事实。

确认 Findings 和写作配置新增折叠选填区“补充你的判断”，包括用途、关注点、取舍、选择，每项最多600字。AI不能填写这组人工输入。已有文章补充后须点击“重新生成文章”，判断仅随新版本保存；不填继续原流程，全部清空表示不使用作者判断。排版设置可以跨测评复用，作者判断不跨 Findings 自动继承。实现与待开展的效果对照见 [作者判断与自然表达](author-perspective-writing.md)。


## v9 确定性检查与细节保留

新增可维护的正文用语列表，检查流程用语、固定连接词、超过2个范围句、超过2处“——”、双层数字方括号和超过5个标签。它们进入 review.deterministicIssues，同时独立标为 editorialOnlyIssues，触发一次修订；不进入失败 Schema 或最终事实门禁。仅这类提示存在时，修订原样返回也可继续独立审核；残留提示保存为 naturalVoiceAudit.remainingIssues，不能用提示命中数冒充内容质量评分。既有实质重复、无依据断言和审核质量要求保持。

修订前提取初稿正文内的引语、数字及单位、拉丁专名和已知产品名；修订返回时逐项比较。引用括号从双层改为单层视为同一编号；数字按完整标记比较，43不匹配143。未被明确要求删除的细节缺失会成为 deterministicIssues，进入既有同 Provider 的有界修复。引用不能转述，只有审稿明确指出该引用过长并要求压缩/转述时例外。事实纠正及明确定位到引语/数值的删除要求允许移除错误信息；泛泛的“删除流程用语”不能授权丢掉整段的具体细节。没有明确删除依据时优先恢复原话，不能由修订者自行删证据。

独立终审继续对照原始 Artifact，检查概括有没有新增产品回答没有的解释；产品关于人物意图的说法须明确归于产品观点，不能由作者当作已验证事实。字面细节比较不能代替语义核对，中文专名识别也并不完整。

与既有诊断/实施记录冲突的边界以本次任务为准：不再将“无作者判断”概括为禁止所有第一人称亲历；可追溯的人工执行动作用第一人称合法，个人体验仍要记录。旧建议中的长引语压缩不适用于关键原话，须有明确审核依据；范围说明集中一处。旧文档和旧稿是历史记录，不回写改造。Provider、Model、集中路由及其 promptVersion 保持原值；策略版本与实际输入/提示内容签名区分v9检查点，生产提示词全文同步清单。

验证计数只表示规则命中、范围句和能在 originalDetails 字面找到的引语/数字条数，不代表自然度提高。自然度需读者随机顺序盲评，本轮不宣称提升。

本轮真实回归另发现模型终审漏过“静默删除引语中间括号说明”。因此在纯文本来源中补充确定性连续原文核对：8字及以上引语须能在 originalDetails 连续找到，排版引号/空白可规范化，明确省略号可分段匹配；发现不一致会形成带定位的 deterministicEvidenceIssues，交给既有修订。该检查属于引用事实核验，不属于上述六类软文风信号。视觉证据中不因文本缺少引语就判错，仍由多模态原始证据审核负责；该字面检查也不能独自证明引语出自回答而非任务，归属仍由独立终审核实。

真实回归还保留两类审稿误判：把原始产品回答误当draft、把原文存在的引语判为不存在。原始证据消息现明确标记“证据而非待审稿”；初审/终审接收程序生成的verbatimTextMatches，字面匹配不代表外部真实性、角色归属或语义审核通过，不能据此自动覆盖审核结论。嵌套引号按成对栈提取，避免截断专名引文。已有TestRun备注从同一原始证据的首个服务端Artifact标签读取；有备注的个人体验仍交独立语义核对，不能仅凭备注非空认定具体经历真实。没有记录时的情绪、耗时、次数和偏好继续被提示，程序模式不是完整语义证明。

保持原有收益/频率/过程门槛，并补齐本轮真实稿暴露的同义写法：无来源的“最常用”等频率泛化、未记录的“省时间”，以及把“快速理解框架”偷换成生成/检索速度快。它们属于事实断言，仍受原有来源检查和两次独立审核约束，不纳入软文风计数。没有改动冻结Findings；其使用影响不自动证明实测速度。
